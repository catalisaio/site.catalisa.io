# Inspirações, decisões e evolução

## Como combinar com outros materiais
Este pacote descreve o site implementado e as decisões expressas nesta conversa. Não é um novo parecer sobre todas as imagens anexadas anteriormente: vários arquivos não estavam acessíveis durante etapas do trabalho. Os títulos das referências forneceram direção, mas não substituem a inspeção visual dos originais.

Na continuidade, reúna as inspirações reais e os documentos já existentes. Não substitua arquivos como AGENTS.md, CLAUDE.md ou convenções do repo. Use um índice que aponte para eles. Quando houver conflito entre um material antigo e uma decisão posterior, registre o conflito e a escolha; não misture direções sem hierarquia.

## Matriz para novas referências
Preencher para cada inspiração:
| Campo | O que registrar |
|---|---|
| Arquivo e origem | Nome, pasta, autor/licença quando conhecido |
| O que extrair | Ritmo, espaço, cor, materialidade, interação ou tratamento de print |
| Onde aplicar | Página e componente específicos |
| O que preservar | Hierarquia, marca e decisões aprovadas |
| O que não copiar | Conteúdo, assinatura ou composição sem relação com o problema |
| Experimento | Uma mudança comparável, com versão anterior disponível |
| Aceite | Leitura, carga cognitiva, identidade e comportamento mobile |

As referências nomeadas como building blocks, caos se organizando, noise become signal, caminho, transformação, gráficos vivos e mobile devem alimentar princípios distintos. Não interpretar todas como a mesma animação ou uma biblioteca de enfeites.

## Registro de decisões
| Decisão | Razão | Evitar na evolução |
|---|---|---|
| Marca e arquitetura primeiro | Construir referência institucional | Converter toda página em formulário comercial |
| Home preservada | Direção visual aprovada | Refazer sem necessidade para uniformizar o site |
| Variação entre páginas | Repetição foi rejeitada várias vezes | Template único para todas as internas |
| Menos carga cognitiva | Riqueza visual precisa de foco | Mais cards, chips e legendas simultâneos |
| Grid no catálogo | Comparação e exploração | Lista longa sem pistas visuais |
| Documentação no começo dos detalhes | Aprofundamento disponível cedo | Link técnico escondido no fim |
| Prints integrados e ampliáveis | Entender produto com contexto | Imagem solta ou ilegível |
| Contato como experiência própria | Conversa e conceito com continuidade | Chat flutuante genérico ou envio sem histórico |
| Nome antes de demo | Identificar contexto antes da exploração | Pedir nome apenas no encaminhamento |
| Lab no topo | Tornar exploração fácil de encontrar | Esconder no rodapé |
| Banking e Credit como estrelas | Produtos mostram a base concretamente | Reduzir ambos ao mesmo card de features |
| Visão como rótulo | Coerência com conteúdo e URL | Voltar a “Sobre” na navegação |

## Prompt-base para novo visual
“Crie uma variação para [componente/página] da Catalisa. Preserve a direção minimalista Bauhaus: papel, roxos, laranja expressivo, geometria com sentido, bastante espaço e uma mensagem dominante. Use [referência] especificamente para [atributo]. A metáfora deve explicar [relação real do produto]. Entregue uma composição própria, diferente de [páginas vizinhas]. Mantenha texto de negócio claro e estados reais/ilustrativos identificados. Proponha desktop e mobile, redução de movimento e como o componente funciona com teclado. Não redesenhe a Home aprovada nem substitua a assinatura.”

## Critério de evolução
Avaliar o resultado em contexto, com o texto final e em sequência com outras páginas. Uma prancha isolada pode ser bonita e ainda produzir um site repetitivo. Só promover uma inspiração para o sistema depois de validar leitura, interação, responsividade e coerência com a marca.
